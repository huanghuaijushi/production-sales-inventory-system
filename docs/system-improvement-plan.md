# 产销存系统后续优化计划

## 1. 背景说明

基于当前前端页面、后端逻辑和数据库结构复查后，系统现状需要修正为：

> BOM、供应商、供货规则、智能采购建议、生产建议、生产工单等功能骨架已经存在，不是没有功能；当前主要问题是数据配置、业务闭环深度、自动化程度和一致性保障还需要继续加强。

之前从数据库直接查看时，当前本地库中：

- `bom_item` 数据量为 0
- `supplier_material` 数据量为 0
- `production_material_issue` 数据量为 0
- `role / permission` 数据量为 0

所以得出的判断是“这些能力没有真正跑起来”。

但从前端页面看，系统已经有：

- 成品配方维护页面
- 供应商资料维护页面
- 供货规则维护页面
- 智能采购建议面板
- 生产建议面板
- 生产工单页面
- 原料批次领用
- 工序损耗记录
- 成品入库

因此更准确的说法是：

> 这些模块已经具备第一版可用功能，但还需要通过数据初始化、流程补强和规则统一，让它们从“能维护、能展示”升级到“能稳定指导经营”。

---

## 2. 当前功能现状复核

### 2.1 生产配置：成品配方

页面：`ProductionConfigView.vue`

当前已有功能：

- 查询成品配方
- 按成品筛选配方
- 搜索成品或原材料
- 新增配方明细
- 编辑配方明细
- 删除配方明细
- 配置单位用量
- 配置损耗率

业务作用：

- 表示生产 1 个成品需要消耗多少原材料
- 用于计算可生产量
- 用于计算原材料缺口
- 用于创建生产工单时生成用料计划

当前评估：

- 功能方向正确
- 页面交互基本完整
- 适合第一版轻量生产管理

当前不足：

- 本地数据库当前 `bom_item` 为空，说明演示数据没有把 BOM 配起来
- 缺少“一键初始化标准配方”的能力
- 缺少配方完整性提示，例如某个成品还没有配方、配方原料不足等
- 缺少配方版本概念，后续如果配方变更，历史工单可能需要保留旧配方快照

结论：

> 不是功能没有，而是需要补数据、补校验、补历史快照能力。

### 2.2 供应商管理与供货规则

页面：`SupplierManagementView.vue`

当前已有功能：

- 新增供应商
- 编辑供应商
- 删除供应商
- 搜索供应商
- 选择供应商查看资料
- 查看当前供应商供货规则
- 查看全部供货规则
- 新增供货规则
- 编辑供货规则
- 删除供货规则
- 维护默认单价
- 维护最小起订量
- 维护采购倍数
- 维护交期天数

业务作用：

- 决定原材料从哪个供应商采购
- 决定采购建议如何按供应商分组
- 决定建议采购数量如何按起订量和采购倍数修正
- 决定预计到货日期如何计算

当前评估：

- 页面功能是比较完整的
- 供货规则字段也比较实用
- 和智能采购建议之间已经有联动设计

当前不足：

- 本地数据库当前 `supplier_material` 为空，说明演示数据没有初始化供货规则
- 缺少“优先供应商”在界面上的显式维护或排序提示
- 缺少多供应商比价能力
- 缺少价格历史
- 缺少供应商启停状态在供货建议里的明确提示

结论：

> 供应商功能不是没有，而是还可以从“维护资料”升级到“采购决策支持”。

### 2.3 采购管理与智能建议

页面：`PurchaseManagementView.vue`

当前已有功能：

- 采购单列表
- 采购单搜索
- 按状态筛选
- 新增采购单
- 编辑采购单
- 取消采购单
- 待入库采购单确认入库
- 智能采购建议
- 生产建议
- 从采购建议生成采购单
- 缺少供应商时跳转绑定供应商

业务作用：

采购模块已经把：

```text
生产建议
-> 原材料缺口
-> 采购建议
-> 按供应商分组
-> 生成采购单
-> 确认入库
-> 增加库存和批次
```

串起来了。

当前评估：

- 采购模块是当前比较成熟的一段闭环
- 采购单确认入库后会调用库存服务，生成库存流水和批次库存
- 业务逻辑方向正确

当前不足：

- 采购建议强依赖 BOM 和供货规则，如果它们没配置，建议会为空或不准
- 缺少采购审批流程
- 缺少部分到货/分批入库
- 缺少采购退货
- 缺少价格变动记录
- 缺少供应商交付表现统计

结论：

> 当前采购模块可以作为第一版主流程继续使用，下一步应增强异常场景和决策能力。

### 2.4 生产工单与批次进度

页面：`ProductionPlanView.vue`

当前已有功能：

- 新建生产工单
- 选择成品
- 按配方生成用料计划
- 无配方时提示去生产配置维护配方
- 工单列表
- 工单详情
- 开始生产
- 取消工单
- 原料批次领用
- 按批次扣减原料库存
- 生成生产领用库存流水
- 记录工序与损耗
- 展示当前工序、本步可处理、本步合格
- 保存并进入下一步
- 成品入库

业务作用：

生产模块已经具备从计划到执行的第一版闭环：

```text
创建工单
-> 根据 BOM 生成用料计划
-> 批次领料
-> 工序报工
-> 记录损耗
-> 成品入库
```

当前评估：

- 功能设计明显比简单库存系统更完整
- 批次领料与库存流水联动是非常合理的
- 工序损耗记录适合食品生产场景

当前不足：

- 本地数据库当前 `production_material_issue` 为 0，说明示例数据没有体现真实领料执行
- 工序流转规则还比较固定，适合第一版，不适合复杂工艺路线
- 缺少质检记录
- 缺少返工/报废/异常停工
- 成品入库成本如何从原料消耗和损耗推导，目前还可以继续增强
- 生产工单和销售需求之间还没有形成明确联动

结论：

> 生产模块已有较好的第一版闭环，下一步重点是补数据、补成本、补质检、补销售驱动。

## 3. 对“BOM、供应商都有了，为什么还说不够”的解释

这里要区分三个层次。

### 3.1 第一层：有没有表

数据库里确实有：

- `bom_item`
- `supplier_material`
- `supplier`

这一层已经有。

### 3.2 第二层：有没有功能页面

前端确实有：

- 成品配方页面
- 供应商资料页面
- 供货规则页面
- 智能采购建议入口

这一层也已经有。

### 3.3 第三层：有没有真实业务数据和闭环能力

当前本地数据库里：

- `bom_item` 为空
- `supplier_material` 为空
- `production_material_issue` 为空

所以对当前本地运行数据来说：

- 生产建议没有真实 BOM 可以依赖
- 采购建议没有真实供货规则可以依赖
- 生产领料没有真实执行样本

因此我说“不够”，不是指功能没有，而是指：

> 功能已经做了，但还没有通过完整数据和规则，把它跑成一个可信的业务系统。

## 4. 推荐优化计划

## 阶段一：补齐演示数据和基础配置

目标：让系统在本地打开后，所有主要功能都有可看的真实数据。

### 4.1 初始化 BOM 配方数据

为当前成品补配方，例如：

```text
豆沙粽 = 糯米 + 豆沙馅 + 粽叶
鲜肉粽 = 糯米 + 猪肉 + 粽叶
蛋黄肉粽 = 糯米 + 猪肉 + 咸蛋黄 + 粽叶
```

落表：

- `bom_item`

收益：

- 生产配置页面不再空
- 生产建议能计算
- 生产工单能生成用料计划
- 原料缺口有真实依据

---

### 4.2 初始化供应商供货规则数据

为当前供应商和原材料配置供货规则。

落表：

- `supplier_material`

建议字段：

- 默认单价
- 起订量
- 采购倍数
- 交期
- 优先供应商

收益：

- 采购建议能按供应商分组
- 采购建议能计算预计金额
- 可以从建议直接生成采购单
- 缺少供应商的提示会减少

---

### 4.3 初始化真实领料记录样本

当前生产工单有用料计划和工序记录，但实际领料表为空。

建议补充：

- `production_material_issue`
- 关联 `stock_record(PRODUCTION_USAGE)`
- 关联原料 `stock_batch`

收益：

- 生产工单详情更真实
- 批次追溯链路更完整
- 首页原料消耗趋势更可靠

---

## 阶段二：补强销售闭环

目标：让销售从“有订单表”升级为“订单驱动库存和看板”。

### 4.4 明确销售单状态流转

建议状态：

```text
PENDING      待发货
SHIPPED      已发货
COMPLETED    已完成
CANCELLED    已取消
```

还可以考虑增加：

```text
LOCKED       已锁库
OUTBOUNDED   已出库
```

如果不想加状态，也至少要在服务层明确：

- 创建订单是否锁库存
- 发货时是否扣库存
- 完成时是否只改状态

---

### 4.5 建立销售出库服务

理想逻辑：

```text
销售单发货
-> 检查可用库存
-> 优先选择批次
-> 扣减 stock_batch
-> 扣减 stock
-> 写 stock_record(SALES)
-> 更新 sales_order 状态
```

收益：

- 首页热销 Top5 真实
- 销售趋势真实
- 成品库存真实
- 批次追溯可以查到销售去向

---

### 4.6 支持锁库

创建销售单时可以先锁定库存：

```text
stock.locked_quantity 增加
stock.available_quantity 减少
```

发货时：

```text
stock.quantity 减少
stock.locked_quantity 减少
```

取消时：

```text
stock.locked_quantity 减少
stock.available_quantity 恢复
```

收益：

- 避免超卖
- 订单未发货也能影响可用库存
- 更接近真实经营

---

## 阶段三：库存一致性与追溯增强

目标：保证库存数据长期可靠。

### 4.7 规定库存唯一写入口

建议强制约定：

> 所有库存变动只能通过 `InventoryService`，不能直接改 `stock`、`stock_batch`。

所有库存变化必须同时维护：

- `stock`
- `stock_batch`
- `stock_record`

收益：

- 报表可靠
- 批次可靠
- 可追溯

---

### 4.8 增加库存一致性检查

建议增加后台检查接口或脚本：

检查项：

```text
stock.quantity 是否等于同 product 下 stock_batch.quantity 汇总
stock.available_quantity 是否等于同 product 下 stock_batch.available_quantity 汇总
stock_record.after_quantity 是否连续
是否存在无批次的批次型库存变动
是否存在负库存批次
```

收益：

- 发现异常数据
- 方便开发阶段排错
- 为以后生产使用打基础

---

### 4.9 增强批次规则

建议增加：

- 先进先出
- 临期优先出库
- 过期不可用
- 手动指定批次

当前生产领料页面已经支持选择批次，这是很好的基础。

下一步可以把销售出库也做成类似规则。

---

## 阶段四：生产成本与质检增强

目标：让生产模块不仅能管数量，也能解释成本和质量。

### 4.10 成品批次成本计算

当前 `stock_batch` 有 `unit_cost` 字段。

建议生产入库时按以下方式计算：

```text
成品批次成本 = 已领原料成本 + 过程损耗成本 + 可选人工/制造费用
成品单位成本 = 成品批次成本 / 入库数量
```

收益：

- 首页库存金额更真实
- 成品毛利更可信
- 生产损耗能体现为成本

---

### 4.11 增加质检记录

可以新增表，例如：

```text
production_quality_check
```

记录：

- 工单
- 批次
- 检查项
- 检查结果
- 不合格数量
- 处理方式

收益：

- 更适合食品生产
- 可以追溯质量问题
- 支持出厂前检查

---

## 阶段五：权限与系统配置收敛

### 4.12 统一权限模型

当前有两种权限痕迹：

- `admin_user.role`
- `role / permission / admin_user_role / role_permission`

建议二选一。

如果系统只给少数人用：

```text
保留 admin_user.role，删除复杂 RBAC 或暂时不启用
```

如果后续要多人、多岗位：

```text
启用 role / permission，admin_user.role 只作为兼容字段或删除
```

---

### 4.13 增加系统设置表

建议新增：

```text
system_setting
```

配置项包括：

- 首页金额显示单位
- 默认预警天数
- 默认保质期策略
- 销售出库批次策略
- 生产工序模板
- 是否启用锁库

收益：

- 避免参数写死在代码里
- 方便小工厂按自己习惯调整
- 后期维护更简单

---

## 6. 修正后的最终判断

更准确的结论是：

> 当前系统不是缺少 BOM 和供应商功能，而是这些功能已经有了第一版页面和接口，但还需要补齐真实配置数据、补强销售闭环、加强库存一致性和生产成本计算。

从当前界面看，系统已经具备：

- 采购管理
- 供应商资料
- 供货规则
- 生产配置
- 智能采购建议
- 生产建议
- 生产工单
- 批次领料
- 工序损耗
- 成品入库

这说明系统方向是比较完整的。

下一阶段重点不应再是“再多加表”，而是：

1. 把现有表的数据补全
2. 把业务闭环打通
3. 把关键口径统一
4. 把库存和报表做准

---

## 7. 一句话计划

> 先补齐 BOM 与供货规则数据，让智能建议真正可用；再补销售锁库与出库闭环，让销售驱动库存；最后做库存一致性、生产成本和系统配置，把系统从演示型产销存升级为可长期使用的小工厂经营系统。
