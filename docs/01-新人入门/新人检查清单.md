# 项目新手上手清单

> 适用对象：第一次接手 HHJS 产销存系统的人
>
> 目标：用最少时间建立整体认知，知道先看什么、先跑什么、先改什么、先避开什么坑。

---

## 1. 先搞清楚这个项目做什么

你先记住一句话：

> 这是一个围绕 **采购、生产、销售、库存、批次、成本、毛利** 的产销存系统。

它不是单纯的“库存管理”。它更像一个轻量 ERP，尤其适合食品生产场景。

### 你需要先理解的主线

```text
采购原材料
-> 原材料入库
-> 生产领料
-> 工序与损耗
-> 成品入库
-> 销售出库
-> 库存流水
-> 收入 / 成本 / 毛利统计
```

---

## 2. 第一周建议按这个顺序看

### 第 1 天：先看文档

先读下面这些文档：

1. `docs/project-handover-guide.md`
2. `docs/development-guide.md`
3. `docs/system-business-data-design.md`
4. `docs/production-purchasing-design.md`
5. `docs/sales-order-import-center-design.md`

#### 你要重点记住的内容

- 哪些是原材料，哪些是成品
- 哪些金额是收入，哪些金额是成本
- 库存、批次、流水三者关系
- 生产成本如何归集
- 销售出库如何形成毛利

### 第 2 天：先跑起来

#### 启动数据库

```bash
docker compose -f docker-compose.dev.yml up -d
```

#### 启动后端

```bash
cd production-sales-inventory-api
mvn spring-boot:run
```

#### 启动前端

```bash
cd production-sales-inventory-web
npm install
npm run dev
```

#### 启动后先确认

- 后端是否能访问
- 前端是否能登录
- 首页看板是否正常显示
- 库存页面是否能打开

---

### 第 3 天：先看首页看板

打开首页，重点看这些模块：

- 原料分类库存占比
- 成品分类库存占比
- 热门商品
- 库存总览
- 毛利 / 收益统计

你要理解：

- 看板按 **库存金额** 统计，不只是按数量统计
- 分类卡片会展示 SKU 数和库存数量
- 库存金额和批次成本是后面所有报表的基础

---

### 第 4 天：先看库存页面

打开库存总览页面，重点看：

- 库存列表
- 库存流水
- 批次选择
- 入库 / 出库弹窗
- 业务金额、成本金额、毛利/损失

#### 你要理解的字段

- `business_amount`：业务金额 / 收入
- `cost_amount`：成本金额
- `stock_batch.unit_cost`：批次单位成本

---

### 第 5 天：看生产模块

打开生产计划页面，重点看：

- BOM 配方
- 生产工单
- 原料领料
- 工序损耗
- 成品入库

#### 你要理解的核心逻辑

```text
原料领料流水 cost_amount
-> 成品入库时汇总
-> 生成批次 unit_cost
```

这一步决定了成本准不准。

---

### 第 6 天：看采购模块

打开采购页面，重点看：

- 供应商资料
- 供货规则
- 智能采购建议
- 采购单
- 确认入库

#### 你要理解的核心逻辑

- 采购主要是给原材料补货
- 生产建议会倒推原材料缺口
- 供货规则会影响建议采购量和预计到货

---

### 第 7 天：看销售模块

打开销售页面，重点看：

- 销售单
- 导入中心
- 销售出库
- 批次扣减
- 实际销售单价
- 毛利统计

#### 你要理解的核心逻辑

- 销售出库会消耗成品批次
- 销售流水会记录收入和成本
- 毛利 = 业务金额 - 成本金额

## 5. 你先记住这些数据口径

### 5.1 数量

表示库存件数，不是金额。

### 5.2 库存金额

表示：

```text
库存数量 × 单位成本
```

### 5.3 成本金额

表示实际成本，用于：

- 领料
- 入库
- 损耗
- 批次成本

### 5.4 业务金额

表示收入，用于：

- 销售出库
- 收益统计
- 毛利分析

### 5.5 批次单位成本

表示某一批货每个单位的成本。

生产批次的单位成本现在由领料成本汇总推导。

## 6. 你先记住这些最容易踩坑的点

### 坑 1：只改前端，不改后端 DTO

如果前端加了新字段，比如售价、成本价、批次成本，后端 DTO 也要同步，否则接口会对不上。

### 坑 2：老数据不会自动变正确

新逻辑只对之后的新流程生效，历史数据不会自动回填。

### 坑 3：数量和金额不要混

- 数量 = 件数
- 金额 = 钱

不要把它们混成一个字段。

### 坑 4：改完记得刷新浏览器

有些页面改完后前端缓存没刷新，看起来像没生效。

### 坑 5：批次为空通常不是页面坏了

常见原因：

- 没选商品
- 商品还没有批次
- 批次接口没返回
- 你看的是旧页面

## 8. 如果你现在要接着干活，建议任务顺序

### 优先级 A：理解业务和跑通环境

- 启动项目
- 登录系统
- 看首页和库存页面
- 看生产页面
- 看采购页面

### 优先级 B：理解数据口径

- 明确业务金额和成本金额
- 明确批次单位成本来源
- 明确库存金额统计方式

### 优先级 C：开始改小功能

- 调整表格样式
- 优化弹窗交互
- 修复字段显示
- 补充文档

### 优先级 D：再动业务逻辑

- 成本归集
- 批次策略
- 导入中心
- 权限体系

---

## 9. 你最应该先回答自己的三个问题

1. 这个功能是管 **数量** 还是管 **金额**？
2. 这笔数据是 **业务金额** 还是 **成本金额**？
3. 这次操作是 **库存变动**，还是 **成本归集**？

如果这三个问题没想清楚，很容易改错。

---

## 10. 最后的建议

你刚接手这个项目时，不要急着加功能。先做到三件事：

1. **跑起来**
2. **看懂主流程**
3. **搞清楚金额口径**

只要这三件事懂了，你后面改代码会顺很多。
